# 产品形态与方案

> 2026-11-24 初稿。记录到目前为止定下来的事，以及还没定的事。

## 1. 一句话

**一个替这本书"值班"的编辑助理**：老师或你提一句需求，它去改书稿、出习题、做课件，自己编译检查，然后把改动交给人审，审过才算数。

它不是"一键生成一本书"的工具。书的质量靠的是三样东西：规范（textbook-writing 那套）、自动检查、人工审核。智能体负责把中间那一大段体力活干掉。

## 2. 谁用，用来干什么

| 角色 | 典型需求 | 能做什么 |
|---|---|---|
| **你（维护者）** | "第 1 章表 1-6 换成最新型号""全书把 X 统一成 Y" | 提需求、审核合并、改配置 |
| **老师** | "第 5 章加一节 GraphRAG""给第 3 章出 10 道期末题" | 提需求、看结果、提意见 |
| 学生（以后） | 问书里的内容、做练习 | 只读，暂不开放 |

## 3. 三个能力，按顺序做

| 阶段 | 能力 | 例子 | 难度 |
|---|---|---|---|
| ① 维护 | 按需求改已有内容 | 更新数据和型号、修错、统一术语、按老师批注改 | 低：改动小，对错好判断 |
| ② 配套 | 根据章节生成习题和课件 | 每章 10 道题（含答案解析）、一讲 PPT | 中：要模板，要验答案 |
| ③ 出新 | 检索资料后写新章节、新教材 | 新增一节、写一本新书 | 高：要大纲、引文核验、多轮审 |

先把 ① 做扎实，② ③ 复用 ① 的整套流程（改 → 编译 → 自检 → 送审），只是"改"的那一步更重。

## 4. 产品形态

### 4.1 用户看到的

- **网页（第一个入口）**：登录后看到一个输入框和任务列表。提交需求后能看到排队位置、当前步骤（读稿 / 改稿 / 编译 / 自检）、最终结果（改动对比、编好的 PDF 预览链接、习题或课件下载）。
- **飞书 / 企业微信机器人（以后）**：在群里 @ 它提需求，做完把结果卡片发回群里。后台和网页是同一套。
- 个人微信机器人不做：非官方协议，号容易被封。

### 4.2 审批方式

智能体**从不直接改正式版**。每个任务在单独的分支上完成，最后生成一个 GitHub PR：左边旧版、右边新版，附编译好的 PDF。你点合并才生效，改错了一键回退。

### 4.3 一个任务的完整过程

```
提需求（网页 / 机器人）
  → 进队列（同一时间只处理一个改书稿的任务）
  → 智能体：读相关章节 + 规范 + 术语表 → 必要时联网检索 → 改稿
  → 编译 PDF：失败就把报错喂回去修，最多 3 次，超了转人工
  → 自检：章节数 / 字数 / 公式数有没有异常减少；术语、符号是否和全书一致；引用是否存在
  → 提 PR，附 PDF 和一段"改了什么、为什么"的说明
  → 通知提需求的人
  → 你审核：合并 / 打回并附意见（打回的意见会作为新一轮任务的输入）
```

## 5. 整体架构

```
   老师 / 你
      │  浏览器
      ▼
┌──────────────────┐  只做转发，几乎不占资源
│ 社团服务器（腾讯云） │  朋友的 nginx 加一条转发规则
└────────┬─────────┘
         │  SSH 反向隧道（树莓派主动连出去，家里不需要公网地址）
         ▼
┌─────────────────────────────────────────────┐
│ 树莓派 5（家里，8G 内存，7×24）               │
│                                             │
│  网页服务 ── 任务队列 ── 智能体核心            │
│                          │                  │
│        ┌─────────┬───────┼─────────┬──────┐ │
│        ▼         ▼       ▼         ▼      ▼ │
│     书稿仓库   LaTeX    检索      引文    规范 │
│     (git)    编译容器  (Tavily)   核验   技能  │
└────────┬───────────────────┬────────────────┘
         │                   │  需要时走代理
         ▼                   ▼
   GitHub 私有仓库         DeepSeek API（运行时模型）
   （书稿源码、PR）
```

### 5.1 各部分说明

| 部分 | 放哪 | 说明 |
|---|---|---|
| 入口转发 | 社团服务器 | 树莓派用 SSH 反向隧道把网页端口映射过去，请朋友在 nginx 里加一个路径或子域名指过来 |
| 网页 + 任务队列 | 树莓派 | 轻量 Python 服务；登录白名单、每人用量上限、任务状态 |
| 智能体核心 | 树莓派 | 循环：调模型 → 执行工具 → 结果喂回去。具体用什么实现见第 7 节 |
| 书稿仓库 | GitHub 私有仓库 | **现在书稿只在本地 git，没有远程仓库**，要先建一个私有仓库。网站继续发布到 zero2hero 的 gh-pages |
| 题库 / 考卷 | 另一个私有仓库 | 和教材物理隔离，智能体出考题时才挂载，绝不推到公开位置 |
| LaTeX 编译 | 树莓派上的 Docker | 固定版本的 TeX Live + 中文字体，保证和本地编出来一样（441 页、无未定义引用） |
| 规范技能 | 树莓派 | 把 `textbook-writing`、`HANDOFF.md`、`SPEC.md` 整理成一份不依赖 Windows 路径的版本 |
| 运行时模型 | DeepSeek API | key 由你提供，只存在树莓派的私密配置里，不进仓库 |

## 6. 质量和安全护栏

1. **编译失败的修复有上限**：最多 3 次，超了转人工，不让它无限乱改。
2. **防"删掉出错的那段来过编译"**：每次比较改动前后的章节数、字数、公式数、图表数，异常减少就拦下。
3. **全书一致性**：术语表、符号表每次都带上；改完跑一致性检查（比如第 5 章 d 和符号表冲突这类问题）。
4. **版面检查**：编译日志里的 Overfull 警告、浮动体位置报告先兜底；`deepseek-flash` 能看图，可以把改动页渲染成图片让它复核（`deepseek-v4-pro` 不能看图）；改了图的页面，PR 里附缩略图给人看。
5. **权限白名单**：智能体只能在书稿目录里读写，只能跑白名单里的命令（编译、检查脚本、git 提交到自己的分支），不能推 main，不能碰考卷仓库（出题任务除外）。
6. **防搜索结果里藏指令**：检索到的网页内容只当资料，不当指令。
7. **人审是最后一道关**：所有改动都要你合并才生效。

## 7. 开发方式和还没定的事

### 7.1 开发方式（2026-11-24 修正）

- **在 Windows 上写代码，打包成镜像给树莓派运行。** 代码由 Claude 开发（主会话 + 子代理），你验收。
- 代码仓库：https://github.com/king157419/BookSmith （**公开仓库**，绝不能提交任何密钥）。
- 树莓派上的项目目录：`~/BookSmith`。
- 执行层：OpenCode 接 DeepSeek，不用 SDK 自己写循环。
- 一次做到 M4（维护、配套、出新三个能力都做）；飞书、企业微信暂不做。
- 字体换成开源字体，之后正式 PDF 也由树莓派编，不再依赖 Windows。

### 7.1.1 部署方式（2026-11-24 调整）

- **本地开发、树莓派只跑镜像**：智能体代码在 Windows 上开发和调试，用 `docker buildx --platform linux/arm64` 打 ARM 镜像，传到树莓派运行。
- **镜像里只放"不常变的环境"**：TeX Live、中文字体、Python 依赖、OpenCode。
- **常变的东西不进镜像**：书稿（Git 仓库）、技能和提示词（Git 管理、挂载进容器）、配置和 key（挂载），改了只需 `git pull` 加重启，不用重新打镜像。
- 只有改智能体代码或换环境时才重新打镜像，用一个脚本完成"打包 → 传输 → 重启"，并保留上一版镜像以便回退。
- 本机 C 盘紧张，先把 Docker 数据目录挪到 D 盘。

### 7.2 还没定的

| 问题 | 选项 | 倾向 |
|---|---|---|
| 智能体核心怎么实现 | A. 自己写循环（OpenAI 兼容 SDK 调 DeepSeek）<br>B. 用现成的开源编码智能体（能接 DeepSeek、能无界面运行、能加载技能） | **倾向 B：OpenCode + DeepSeek**（调研见 docs/02）。M1 用它跑通测试任务，不顺再换 A |
| 课件格式 | 套现有模板 / PPT Master / PPTAgent / paper2slides 都可以 | 先选一个最适配的做默认，再出几套风格给你挑 |
| 习题格式 | 直接导出 PDF，学生版不带答案 | 内部保留答案用于校验题目（见对话中的建议） |
| DeepSeek 型号 | 主力 `deepseek-flash`（1M 上下文、能看图、便宜）；难的任务试 `deepseek-v4-pro` | key 到手后用测试任务实测对比 |

## 8. 里程碑

| 编号 | 内容 | 验收标准 |
|---|---|---|
| M0 环境 | 书稿建私有仓库；树莓派上装好 Docker 版 TeX Live 和中文字体 | 在树莓派上编出和本地一致的 441 页 PDF |
| M1 维护（命令行） | 在树莓派上给一句需求 → 改稿 → 编译 → 自检 → 提 PR | 跑通 3 个固定测试任务，PR 内容正确 |
| M2 网页 | 网页、登录、任务队列、进度展示；社团服务器转发上线 | 老师能从外网提需求，看到进度和 PR |
| M3 配套 | 习题（含答案和验算）、课件（套现有模板） | 给一章出 10 道题、一讲课件，人工审核通过 |

## 9. 需要你准备的

1. DeepSeek API key（存到树莓派私密配置）
2. 在 GitHub 上建一个书稿的私有仓库
3. 请朋友在社团服务器的 nginx 里加一条转发规则（M2 时再弄）
4. 确认树莓派上给智能体用的目录（比如单独一个用户或 `/srv/textbook-agent`）
