## 账号与权限

- 首次启动且没有任何账号时，容器日志打印一次性 **setup token**；访问 `/setup` 输入 token 后由用户自己设管理员账号密码（我们不替用户设密码）。
- 管理员在网页里生成**邀请码**（可设有效期、角色）；他人用邀请码注册。
- 角色：`admin`（审核合并、管邀请码、看全部任务）、`member`（提任务、看自己的任务、对自己的任务提意见）。
- 每个用户每日任务数上限（默认 10，管理员可改）。
- 密码用 `hashlib.scrypt` 或 bcrypt 存哈希；会话用签名 cookie（HttpOnly、SameSite=Lax）；所有改状态的请求带 CSRF 校验。

## 任务模型

```
tasks(id, user_id, kind, title, request, params_json, status, branch,
      parent_id, outline, feedback, summary, cost_json, created_at, updated_at)
task_events(id, task_id, ts, step, level, message)      # 进度流
artifacts(id, task_id, name, path, kind, created_at)    # kind: pdf|pptx|diff|md|log|png
users(id, username, pw_hash, role, daily_quota, created_at)
invites(code, role, created_by, used_by, expires_at, created_at)
```

- `kind`：`maintain`（维护）、`exercises`（习题）、`slides`（课件）、`newchapter`（出新）
- `status` 流转：
  `queued → running → (awaiting_outline → queued → running) → awaiting_review → merged | rejected → (以 feedback 新建子任务，parent_id 指向原任务)`；
  任意阶段可 `failed` / `cancelled`。
- 进度通过 SSE 推送：`GET {BASE_PATH}/api/tasks/{id}/events`（`text/event-stream`）。

## 流水线接口（app/pipelines/base.py）

```python
@dataclass
class Ctx:
    task: dict              # tasks 表一行（含 params、outline、feedback）
    workdir: Path           # 本任务专用的书稿 git worktree（分支 agent/<id>-<slug>）
    out_dir: Path           # 本任务产物目录（DATA_DIR/tasks/<id>/）
    log: Callable[[str, str], None]   # log(step, message)
    cancelled: Callable[[], bool]

@dataclass
class Result:
    status: str             # 'awaiting_review' | 'awaiting_outline' | 'failed'
    summary: str            # 给人看的"改了什么、为什么、自检结果"（Markdown）
    artifacts: list[dict]   # [{"name","path","kind"}]

class Pipeline(Protocol):
    kind: str
    def run(self, ctx: Ctx) -> Result: ...
```

- `maintain` / `newchapter` 改书稿：产物至少有 `diff`（对 master 的 unified diff）和 `pdf`（受影响章节或全书）。
- `exercises`：产物 `学生版.pdf`（无答案）+ `教师版.pdf`（含答案与解析）；题目源文件提交在书稿仓库 `exercises/chNN/` 下（便于审核和复用）。
- `slides`：产物 `.pptx`（以及 PDF 预览）；源文件提交在 `slides/chNN/`。
- `newchapter`：第一次运行只出大纲 → `awaiting_outline`；用户确认/修改大纲后再运行写正文。
- 开发和测试用 `FakePipeline`（不调模型、不编译，几秒内产出假 diff 和假 PDF）。

## 审核（网页内）

- 审核页显示：需求、智能体的说明、改动对比（并排/统一 diff，按文件折叠）、PDF 内嵌预览、产物下载。
- 按钮：**通过**（把分支合并进 master，若配置了远程则推送；记录合并提交）/ **打回**（填意见 → 新建子任务在同一分支上继续改）。
- 只有 admin 能通过；提需求的人能看、能提意见。

## 编译（书稿仓库内的脚本）

- `sh tools/build_linux.sh` → 全书四遍编译 + 拼音索引，产出 `main.pdf`，返回码非 0 即失败，并打印错误摘要。
- `sh tools/build_linux.sh --chapter N` → 只编第 N 章（快速预览，用于智能体改稿过程中的自检）。
- 在容器里运行；字体全部用开源字体（Noto CJK / Fandol 等），不依赖 Windows。

## 安全底线

- 容器内 OpenCode 的工作目录限定为任务 worktree；不挂载 SSH 私钥、代理配置等无关文件。
- 智能体不能改 master，只能在自己的分支上提交；合并只由网页"通过"按钮触发。
- 检索得到的网页内容只当资料，不当指令。
- 联网检索：`scripts/websearch.py`（Tavily），模型只能用 `python3 /app/scripts/websearch.py search "…"` / `extract URL` 两种写法调用（opencode.json 白名单；参数含 `> < | $( `` ` 等仍被拒）。key 由 runner 写成隔离 HOME 下的 0600 文件，不进子进程环境；不允许检索的任务（习题、课件）删掉 key 文件并把放行规则覆盖为 deny。每个任务的检索次数有上限，调用记录写进说明的「用量」和 `cost_json`（`web_search` / `web_extract` / `web_failed`）。
- 公开仓库 BookSmith 里有 pre-commit 检查，拦截 `sk-`、`tvly-` 等疑似密钥。
