# 写作规则（展开版）

这些规则来自书的作者和审校人反复纠正过的问题。用户最不能接受两件事：**读起来像 AI 写的**，以及**只说"有什么"、不讲"怎么工作"**。

## 一、五条硬规则

1. **自上而下，问题驱动。** 先讲有什么需求，再讲用什么方案，最后讲效果与代价。用提问开头、用过渡句衔接来体现，**不要**在每节贴"需求 / 方案 / 效果"标签。
   - 好：`为什么让标注员\emph{排序}而不是直接\emph{打分}？不同人对“7 分”和“8 分”的理解差异很大……`
   - 差：`【需求】……【方案】……【效果】……`
2. **先讲机制，比喻放后面。** 先一句话说清它怎么工作（数据从哪来、经过什么、到哪去），再分步展开；比喻只做记忆钩子。地基先讲：讲 KV 缓存之前先讲模型怎么生成一个字。
3. **术语第一次出现就解释。** 缩写写全称加中文，不能先用后讲，总览图里也一样。每个新术语进本章术语表。
4. **只把同一层级的东西并列。** 有包含、调用、先后关系要明说（CUDA 在 PyTorch 下面；ZeRO 是数据并行的一种改进）。图里的箭头要标含义。
5. **易混的词主动辨析。** 同名不同物提醒读者（解码器 vs 解码阶段；"推理"的两种意思）；相近概念用对比表或 `pitfall` 框（MCP / Skill / Function Calling / A2A；SFT / RLHF；Top-K / Top-P）。

## 二、句子层面

- **指代交代清楚**：说"三部分"就点出是哪三部分；说"在此基础上"就说清基础是什么。
- **不写纯声明句**：删掉"XX 非常重要""具有重要意义""随着技术的发展"。每句话要么给事实，要么给机制，要么给判断的依据。
- **修正语病**：如"模型包含复杂的张量运算"是搭配错误，应为"模型的计算涉及大量张量运算"。
- **说人话，少用缩写**，不追求高深；读者读完要有实际收获。
- **作者口吻，不是检索者或 AI 口吻。** 反例（全部禁止）：
  - "作者未能取得原文，转引自……"
  - "经多篇资料转引互相印证"
  - "具体以原文为准"
  - "答题时应……""有的题目要求……""有的资料/教学资料中常见……"
  - "综上所述，我们可以看出""值得注意的是""需要指出的是"（可以直接写那件事）
  - "作为一个 AI……"
  来源靠 `\cite` 交代；拿不准的事实不写进正文，放进说明里请人核实（或在正文里写"截至某年某月，公开资料显示……"并配引用）。
- **不提"课件""第几讲"**：教材独立成书，别的章一律写"第 4 章""第\,\ref{…}\,节"。
- **时效内容**写"截至 2026 年 11 月"，说明信息来源性质（官方文档 / 论文 / 媒体报道）。
- 解释新东西时，尽量接回前面章节的知识点，如用"速度上限 ≈ 带宽 ÷ 权重"解释极速模型为什么快。

## 三、加粗与强调

- 强调统一用 `\emph{}`（黑体），不用 `\textbf`；全书"要么都加粗要么都不加"。
- 术语首次出现用 `\term{}`；一段里强调的词不超过两三个。
- 不用 emoji、不用感叹号、不用口语化的"哈""咱们"。

## 四、计算题怎么写（"小学生看了也会做"）

- 每种题型：**一道例题 + 一道练习**，练习的提示也一步步写全。
- 例题用 `example` 框里的五列表：步骤 / 算什么 / 算式 / 结果 / 这个数从哪来；表后一行"数据流向"；最难的题配流程图。
- 除法和科学计数法加括号：`(7\times10^{9}\times2)\div(1024^{3})`。
- 先算精确值，**中间结果不四舍五入后再继续算**；最终结果的有效数字与题目给的数据相称。
- 与论文、官方数据或课件结果不一致时，**两种结果都列出**，说明差在哪（取整？口径？笔误？），写清考试时怎么写。
- 改完例题数值后，同步：表里每一步、正文引用处、习题提示、图里标注、小结里的公式汇总表。

## 五、配图规范（按 Nature 示意图规范）

- 同一层级字体字号一致，全图最多 2 个字号（9pt 层名/标题、7.5pt 标注），只有层名加粗。
- 作用相同的框宽度一致、位置对齐，各层内部排列顺序一致；关键元素放视觉中心；元素不能挤在一起，也不能顶到边框。
- 图中文字用正文字体（宋体 + Times），**绝不用微软雅黑或无衬线字体**；图中不用数学模式。
- 颜色有固定含义：蓝色（accent）= 当前讨论的对象；红色（warn）= 硬性上限、瓶颈、易错点；其余灰黑。
- 多画框架图，让读者看清这个知识点在整个大模型工程里处于哪一层、哪一步。
- 每章至少一张本章知识地图（各节关系）；每个核心机制一张流程图。

## 六、章与节的骨架（写新内容时对照）

- 章首：2～3 段问题驱动的导语 → 学习目标（5～7 条）。
- 每节：`guide` 一段话 → 正文（先机制后例子）→ 例题/辨析框 → （可选）`keypoints`。
- 章末：小结（逐节回顾"回答了什么问题"）→ 习题 → 本章术语 → 参考文献。
- 篇幅以讲透为准，不追求长；重复和注水的段落删，知识点不要丢。

## 七、事实与引用

- 年份、机构、模型参数、论文结论、数字，都要有出处；能回到原始资料就别用转引。
- 不能确认的数字不要写进正文；确需保留时写成有出处的说法，并在最终说明里列入"待人核实"。
- 公式、符号要符合 `front/notation.tex`；GB 按 $10^{9}$ 字节。
- 自己算过的数字，要把算式写在书里（例题或提示），不要只给结果。
